04 · Experimenting with models: a fair comparison, leakage, and a neural network¶

Series: Exploring the ZTF Bright Transient Survey to find Type Ia supernovae

  2. Visualising with matplotlib & seaborn
  3. Finding patterns & a first Ia classifier
  4. Experimenting with models ← you are here

Notebook 3 built a correctly evaluated baseline with two models: logistic regression (ROC AUC ≈ 0.70) and gradient boosting (≈ 0.90). This notebook asks:

  1. Does the choice of model matter? We line up a dozen classifiers commonly used on tabular data and compare them on equal terms.
  2. How does leakage affect each model? We rerun the line-up with the leaky redshift features, and look for other routes leakage can take.
  3. Can a neural network do better? The finale: what a neural network is, how to watch one learn (and overfit), how to tune it, and how it does on the test set.

Ground rules. These are the same as in notebook 3, so the numbers are comparable:

  • The same PHOTOMETRIC features: only what's known when a transient is detected.
  • The same train/test split (random_state=42) and the same 5 cross-validation folds.
  • Every decision (which model, which settings) is made with cross-validation on the training set. The test set is used once, in section 6.

1 · The line-up¶

Model Family The idea in one line
Dummy baseline Always predicts the majority class.
Logistic regression linear A weighted sum of the features, squashed into a probability.
Logistic regression + squares linear + feature engineering The same, but also given every feature squared and every pair multiplied together, so it can bend.
Naive Bayes probabilistic Models each feature's distribution in each class, assuming the features are independent.
k-nearest neighbours similarity Finds the 50 most similar training objects and reports the fraction that are Ia.
Support vector machine kernel Finds the widest possible boundary between the classes, in a transformed space where curved boundaries become straight.
Decision tree tree One tree of yes/no questions, such as "is log_fade > 1.1?".
Random forest tree ensemble 500 trees, each grown on a random resample of the data, averaged.
Extra trees tree ensemble Like a random forest, but the split points are also chosen at random.
AdaBoost boosting Small trees grown in sequence, each giving more weight to the objects the previous ones got wrong.
Gradient boosting boosting Trees grown in sequence, each one fitted to the errors that are left.
Hist. gradient boosting boosting A faster gradient boosting that bins the features first. Notebook 3's model; scikit-learn's version of the LightGBM algorithm.
XGBoost boosting The library that made gradient boosting famous in ML competitions. It grows trees level by level, to a fixed depth.
LightGBM boosting Microsoft's gradient boosting library. It bins features and grows each tree leaf by leaf, always splitting where the error drops most.
Neural network (MLP) neural network Layers of simple units. Default settings here; section 5 looks at it properly.

Preprocessing. Most of these models can't handle missing values, and several (k-NN, SVM, logistic regression, the neural network) are sensitive to the scale of each feature, because they measure distances or add up weighted features. So a small helper, prep(), puts an imputer and a scaler in front of each model. Trees don't need scaling, but it doesn't hurt them either. The three histogram-style boosting models (scikit-learn's, XGBoost and LightGBM) handle missing values themselves, so they get no prep().

XGBoost and LightGBM are separate libraries, not part of scikit-learn. They provide scikit-learn-style classes (fit, predict_proba), so they work with cross_validate, GridSearchCV and pipelines like every other model here.

SimpleImputer(add_indicator=True) fills each missing value with the column's median and adds a 0/1 column saying "this value was missing". Among the photometric features, only A_V has missing values (23 objects), so the flag barely matters here. It matters a lot in section 3.

The settings below are sensible fixed values, not tuned ones. Sections 4 and 5 tune the two strongest families.

In [3]:
def prep(*steps):
    # Fill missing values (and flag them), standardise, then run the given steps.
    return make_pipeline(SimpleImputer(strategy="median", add_indicator=True), StandardScaler(), *steps)

2 · Cross-validated comparison¶

cross_validate is a bigger version of cross_val_score. It also returns the score on the folds the model trained on (return_train_score=True) and how long each fit took. n_jobs=-1 runs the 5 folds in parallel on all CPU cores.

The SVM has no predict_proba. It outputs a score whose sign says which side of the boundary an object is on. ROC AUC only needs a ranking, so scikit-learn uses that score directly.

In [4]:
def compare(models, X, y):
    rows = []
    for name, model in models.items():
        r = cross_validate(model, X, y, cv=cv, scoring="roc_auc", return_train_score=True, n_jobs=-1)
        rows.append({"model": name, "CV AUC": r["test_score"].mean(), "± (fold std)": r["test_score"].std(),
                     "train AUC": r["train_score"].mean(), "fit time (s)": r["fit_time"].mean()})
    return pd.DataFrame(rows).set_index("model").sort_values("CV AUC", ascending=False)


honest = compare(models, X_train, y_train)

What it shows:

  • The top is a tie. Seven models score between 0.881 and 0.892. The differences are no bigger than the fold-to-fold spread (the error bars), so these numbers can't pick a winner.
  • The features set the ceiling, not the model. Once a model can represent the Ia "sweet spot" (fade by half in 10–20 days), it reaches about 0.89. Getting past that needs more information (colour, full light curves), not a cleverer algorithm.
  • Feature engineering can matter more than the choice of model. Plain logistic regression scores 0.715. The same model, given squared features, scores 0.864. With both x and x² available, a weighted sum can form a hump, −(x − c)², which is high only near a middle value c. That's exactly a sweet spot.
  • XGBoost and LightGBM bring no magic. LightGBM's defaults score the same as scikit-learn's hist. gradient boosting, which copies its algorithm. XGBoost's defaults do worse: its trees go 6 levels deep and its learning rate (0.3) is 3× scikit-learn's. It scores 0.999 on its own training data and memorises more than it learns. Section 4 tunes all three.
  • Naive Bayes (0.835) is held back by its "naive" assumption. Rise, fade and duration are strongly related (duration is roughly rise + fade), so it counts the same evidence two or three times.
  • Train AUC vs CV AUC. The random forest scores 0.99 on data it trained on and 0.89 on unseen data. A large gap means the model memorises its training data. That isn't automatically bad: the CV number is the one that counts. A single decision tree has a large gap and a low CV score, which is real overfitting. A forest averages 500 trees, and their individual mistakes cancel out.
  • Speed isn't a concern at 6,000 objects: everything trains in seconds. It would be on the millions of alerts a night that the Rubin Observatory's LSST will produce.

Almost every CV / nova and AGN has no redshift. Galactic CVs are inside our own Galaxy, so they have no cosmological redshift to measure. Almost every supernova has one. So "no redshift" practically means "not a supernova", and therefore "not Ia".

A model only sees missingness if it's given a way to. HistGradientBoostingClassifier sees NaN directly, and our prep() adds a "was missing" flag. Here's the same leaky logistic regression with that flag switched off and on:

About a third of the inflation comes from whether the values exist at all, not from the values themselves. The lesson is that removing a leaky feature means removing it completely. Filling its gaps isn't enough, because the pattern of gaps can carry the label.

Other routes for leakage: a checklist¶

Route How it would happen here How this notebook avoids it
Features not known at prediction time redshift, peakabs, host properties, the IAU name prefix use only PHOTOMETRIC

4 · Tuning the boosting models¶

So far every model ran with fixed settings. Settings chosen before training, such as the number of trees or how deep they go, are called hyperparameters. A fair fight against a tuned neural network needs tuned opponents too. Boosting is the strongest classical family here, and there are three libraries for it, so all three get tuned.

GridSearchCV tries every combination of the values you list, cross-validates each one, and keeps the best. Each library names its settings differently, so the grids below match them up, with 18 combinations each:

What it controls scikit-learn LightGBM XGBoost
how big a correction each new tree makes learning_rate learning_rate learning_rate
how complex each tree can be max_leaf_nodes num_leaves max_depth
how much data each final group ("leaf") must hold; bigger means smoother, less memorising min_samples_leaf min_child_samples min_child_weight*

* XGBoost doesn't count objects in a leaf. It limits their total "weight", which is roughly the number of objects × p(1 − p), so its values are smaller.

GridSearchCV is itself a model. After the search, it refits the best combination on the whole training set; that refitted model is search.best_estimator_. cv_results_ is a dict with one entry per combination; "mean_test_score" holds each combination's cross-validated AUC.

What it shows:

  • After tuning, the three libraries are indistinguishable, all at about 0.892. They're the same idea, gradient-boosted trees, with different engineering. XGBoost gains the most because its defaults were the worst fit for this data.
  • All three prefer small trees: 7 leaves, or 3 levels deep, against default limits of 31 leaves or 6 levels. With only 10 summary features, and noisy ones, simpler trees generalise better.
  • The top five settings of each search are within about 0.002 of each other, so the exact values hardly matter.
  • The libraries' real differences are speed and features at scale (GPU training, millions of rows, categorical features), not accuracy on a small table.
  • Winner's curse: the best of 18 cross-validated scores is slightly optimistic. Picking the maximum also picks up whatever lucky noise that combination had. The test set in section 6 gives the unbiased number.

5 · The finale: a neural network¶

What is a neural network?¶

The classic neural network for tables of features is the multi-layer perceptron (MLP). It's built from simple units ("neurons"). Each unit:

  1. takes a weighted sum of its inputs plus a constant: z = w₁x₁ + w₂x₂ + … + b, then
  2. passes it through an activation function. The default is ReLU, max(0, z): zero if z is negative, z itself otherwise.

Units are arranged in layers:

11 inputs  ──►  64 units  ──►  32 units  ──►  1 output = P(Ia)
(features)      hidden 1       hidden 2       (a sigmoid squashes it into 0–1)

MLPClassifier(hidden_layer_sizes=(64, 32)) builds exactly this. There are 11 inputs: the 10 features plus prep()'s "A_V was missing" flag. With no hidden layers, an MLP is logistic regression. The hidden layers, and the bend that ReLU puts in each unit, let it build curved boundaries, such as the fade-time sweet spot.

Training. The weights start random. The network is repeatedly shown small batches of training objects. Each time, it measures how wrong its probabilities are (the loss) and nudges every weight slightly in the direction that reduces the loss. That's gradient descent. Backpropagation is the bookkeeping that works out which way to nudge each weight, and scikit-learn's default optimiser for the steps is Adam. One pass through all the training data is an epoch.

Why scaling matters. Every weight gets a similar-sized nudge, so a feature measured in the hundreds would swamp one measured in tenths. That's why the network sits behind prep().

scikit-learn vs PyTorch / Keras. For 6,000 objects with 10 features, MLPClassifier trains in seconds on a CPU, and a GPU would make no difference. PyTorch or Keras become necessary for images, for sequences such as full light curves, or for custom architectures. The ideas are the same.

Watching a network learn, and overfit¶

To see training happen, we hold out 20% of the training set as a validation set. Then we train one epoch at a time with partial_fit and record the AUC on both parts as we go. Two networks:

  • big and unregularised: two layers of 256 units, alpha=0;
  • small and regularised: (64, 32), alpha=0.01. alpha is a penalty on large weights (L2 regularisation), which discourages the network from bending itself around individual objects.
In [11]:
X_fit, X_val, y_fit, y_val = train_test_split(X_train, y_train, test_size=0.2, stratify=y_train, random_state=0)
prep_only = prep().fit(X_fit)                                    # imputer + scaler, learned from X_fit only
A_fit, A_val = prep_only.transform(X_fit), prep_only.transform(X_val)

nets = {"Big, unregularised: (256, 256), alpha = 0": MLPClassifier(hidden_layer_sizes=(256, 256), alpha=0, random_state=0),
        "Small, regularised: (64, 32), alpha = 0.01": MLPClassifier(hidden_layer_sizes=(64, 32), alpha=0.01, random_state=0)}
history = []
for name, net in nets.items():
    for epoch in range(1, 301):
        net.partial_fit(A_fit, y_fit, classes=[0, 1])           # one more epoch of training
        if epoch % 5 == 0:
            history.append({"net": name, "epoch": epoch,
                            "training": roc_auc_score(y_fit, net.predict_proba(A_fit)[:, 1]),
                            "validation": roc_auc_score(y_val, net.predict_proba(A_val)[:, 1])})
    n_weights = sum(w.size for w in net.coefs_) + sum(b.size for b in net.intercepts_)
    print(f"{name}: {n_weights:,} weights, trained on {len(X_fit):,} objects")
history = pd.DataFrame(history)

What it shows:

  • The big network overfits. Its training AUC climbs towards 1.0 because it's memorising the training objects. Its validation AUC peaks within the first few epochs and then falls. It has about 70,000 weights to fit 4,700 objects, so it has more than enough freedom to memorise noise.
  • The small, regularised network improves more slowly, holds its peak for much longer, and declines only gently.
  • The two standard defences are regularisation (alpha, and smaller networks) and early stopping: stop training when the validation score stops improving. MLPClassifier(early_stopping=True) does this automatically. It sets aside 10% of whatever data it's trained on and stops after 10 epochs without improvement.

Seed 0, the one the grid search happened to use, is the luckiest of the eight. The typical network is a little weaker than the grid-search score suggested. This is the winner's curse again, and it's why a score difference of 0.005 between two models shouldn't be trusted.

A standard way to remove this luck is an ensemble: train several networks with different seeds and average their probabilities. VotingClassifier(voting="soft") does that averaging, and it behaves like any other model:

The ensemble scores better than the average single network, and gets that score reliably, without depending on a lucky seed.

6 · The verdict: the test set, used once¶

All the decisions are made, so each contender is now fitted on the full training set and scored on the test set.

One test set is still one sample of 1,958 objects, and a different sample would give a slightly different AUC. To see how much, we use the bootstrap: resample the test set with replacement 1,000 times, recompute the AUC each time, and report the range covering the middle 95% of the results.

def paired_difference(y_true, p_a, p_b, n=1000, seed=0):
    # Bootstrap the difference in ROC AUC between two models scored on the same objects.
    rng = np.random.default_rng(seed)
    diffs = []
    for _ in range(n):
        i = rng.integers(0, len(y_true), len(y_true))
        diffs.append(roc_auc_score(y_true.iloc[i], p_a[i]) - roc_auc_score(y_true.iloc[i], p_b[i]))
    return {"AUC difference": f"{roc_auc_score(y_true, p_a) - roc_auc_score(y_true, p_b):+.3f}",
            "95% interval": f"{np.percentile(diffs, 2.5):+.3f} to {np.percentile(diffs, 97.5):+.3f}",
            "network ahead in": f"{np.mean(np.array(diffs) > 0):.1%} of resamples"}

The verdict on the neural network. It's competitive but not better:

  • Random split: tuned gradient boosting is ahead by 0.008 AUC. That's small, but the paired bootstrap says it's real: the 95% interval excludes zero, and the network comes out ahead in fewer than 1% of resamples.
  • Future years: the network ensemble is ahead by 0.005. But the 95% interval includes zero, so this could easily be luck.

So neither model wins on both tests, and every difference is under 0.01. Bootstrap intervals tell apart a real edge (the first case) from noise (the second). That's a common result: on small tables of hand-made summary features, tree ensembles are very hard to beat, and neural networks usually match them at best (see Grinsztajn, Oyallon & Varoquaux 2022, "Why do tree-based models still outperform deep learning on tabular data?").

Neural networks pull ahead when the input is raw and structured: images, or full light curves as time series, where the network can learn its own features instead of relying on our 10 summaries. For SN Ia, that's how classifiers like RAPID (Muthukrishna et al. 2019) work. It's the natural next step for this project.

Summary: what I learned¶

About comparing models

  • The features set the ceiling. Every model flexible enough to represent the timescale "sweet spot" reaches ROC AUC ≈ 0.89 in cross-validation and ≈ 0.90 on the test set. The choice of model among them barely matters.
  • XGBoost and LightGBM are not magic. Once tuned, the three gradient-boosting libraries (scikit-learn, XGBoost, LightGBM) are indistinguishable at CV AUC ≈ 0.892. XGBoost's default settings overfit this small dataset.
  • Feature engineering can beat model choice. Logistic regression with squared features jumps from 0.72 to 0.86.
  • A gap between train and CV scores signals memorising. What matters is the CV score; ensembles of many trees memorise and still generalise.
  • Don't crown a winner on a difference of 0.005. Fold-to-fold spread, random seeds and the winner's curse are all about that size. Use bootstrap intervals, and compare two models on the same resamples (a paired comparison).

About leakage

  • Leakage inflates every model (by up to +0.2 AUC here), and the weakest models gain the most. It also hides the real differences between models.
  • Missingness itself can leak. About a third of the inflation came from whether redshift features exist, not their values. Remove leaky features completely.
  • Keep a checklist: features known at prediction time, missingness, preprocessing inside the CV folds, duplicates across the split, no tuning on the test set, time order.

About neural networks

  • An MLP is layers of weighted sums with a bend (ReLU). With no hidden layers it is logistic regression.
  • Large networks overfit fast: validation AUC peaked within a few epochs while training AUC kept climbing. Early stopping and regularisation are the standard defences.
  • Seeds matter: retraining with a different random start moved the score as much as switching models. Averaging several networks (an ensemble) removes most of that luck.
  • On these 10 summary features, the tuned network comes within 0.01 of gradient boosting. It's narrowly but measurably behind on the random test split, and slightly but not significantly ahead on future years.
